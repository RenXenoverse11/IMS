Design Notes

  • OTP stored inline in users: No separate OTP table. Fields otp_hash, otp_expires_at, otp_attempts, and otp_last_sent_at live directly on the user row.
  • Dual task tables: activity_logs is the intern's task view; supervisor_task is the supervisor's. They link via source_activity_id — source_type = "intern" when a supervisor creates a task from an intern activity.
  • Dual project tables: proj_intern is the canonical record. proj_supervisor mirrors it and adds a supervisor_archived flag per supervisor. poj_supervisor (typo sheet) is a legacy copy of the same structure.
  • Members & supervisor columns in projects are comma-separated user_id strings — no separate join table.
  • recent_activities uses an email address (not user_id) as the user key — lightweight feed separate from the full task system.
  • user_settings stores all notification preferences as one settings_json object with keys: document_uploads, request_status_updates, inactive_student_alert, time_log_reminder.
  • No enforced FK constraints: Google Sheets has no native foreign keys. All referential integrity is maintained in GAS server-side code.
